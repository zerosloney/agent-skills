# 编译流程详细指南（Two-Step Compile）

## 为什么要 Two-Step

直接"读取素材→写页面"容易导致：
- 分类错误（选了错误的 entity_type）
- 遗漏已有知识（没有关联已有页面）
- 内容偏离 purpose（知识库方向不一致）
- 无效返工（写到一半发现方向错了）

**Two-Step 把"分析"和"生成"分离**，确保方向对了再动手。

---

## Step 1：Analyze（分析）

读取 `raw/` 素材后，先输出分析，**不写任何文件**。

### Analyze 输出模板

```markdown
## 📋 分析：{素材标题}

### 原始素材
- 来源：raw/{filename}
- 字符数：约 N 字
- 主题标签：{tag1}, {tag2}

### 实体类型判定
- 判定类型：{type}
- 分类依据（按优先级）：
  1. 判断点1 → 类型A
  2. 判断点2 → 类型B
  （最终结论）

### 核心概念提取
1. **{概念A}**：{1句话精确定义}
2. **{概念B}**：{1句话精确定义}

### 关联已有知识
- [[已有页面X]] — 关联方向：补充（X 缺少 Y，这里补全）
- [[已有页面Y]] — 关联方向：扩展（Y 讲理论，这里讲实践）
- ⚠️ [[不存在]] — 知识空白，建议作为新页面候选

### 与 purpose.md 对齐
- 覆盖范围：✅ 属于 AI/ML（purpose 范围内）
- 知识深度：适合作为 concept 类型，3-5 个核心知识点

### 知识缺口
- [ ] {缺口1}：现有 wiki 未覆盖
- [ ] {缺口2}：{素材} 引用但未展开

### 编译决策
- ✅ 新建页面：{建议标题}.md（entity_type: {type}）
- 或：更新页面 [[已有页面]] — 新增章节 {章节名}
- 或：合并到 [[已有页面]] — 作为"## 补充"区块

### Counter-Arguments 评估
- 当前来源数量：N（阈值：≥3 才触发）
- 对立观点：（来源B的不同观点，如有）
```

### 用户确认（等待输入）

输出 Analyze 后，等待用户输入：
- `y` / `yes` → 确认，开始 Generate
- `n` / `no` → 取消
- `revise {内容}` → 修正方向后重新 Analyze
- `merge [[已有页面]]` → 改为合并到指定页面

---

## Step 2：Generate（生成）

用户确认后，执行生成。

### 新建页面的 Generate 步骤

1. **读模板**：`read_file schema/page-template.md`
2. **确定文件名**：英文小写 + 连字符，50 字符内
3. **写 frontmatter**：
   ```yaml
   ---
   entity_type: {type}
   confidence: {high/medium/low}
   domains: [{领域1}, {领域2}]
   sources: [raw/{filename}]
   ---
   ```
4. **按 entity_type 写必需章节**（见 entity-types.md）
5. **建立交叉链接**：
   - 新页面 `## 相关页面` 指向已有页面
   - 同时编辑已有页面的 `## 相关页面` 添加回链
6. **更新 index.md**：添加条目（小型 wiki）
7. **输出完成摘要**

### 更新页面的 Structured Diff

**不直接修改**，先输出 Diff：

```markdown
## 📝 页面更新：{页面标题}

### Current（当前内容）
> {现有描述...}
> 来源：[[已有页面]]

### Proposed（建议修改）
> {修改为...}
> 新增内容：{具体新增/修改的段落}

### Reason（修改理由）
> - 原因1：{...}
> - 原因2：{...}

### Source（来源依据）
> - raw/{filename}：{具体引用}
> - {来源描述}

### 影响评估
- 交叉链接：{新增/减少} N 个
- Counter-Arguments：{触发/不触发}
```

等待用户 `y` 确认后才执行修改。

---

## 特殊情况处理

### 同一主题多个 raw 文件

合并编译：把所有相关 raw 文件都读完后，合并分析，再生成一页。

```markdown
## 📋 分析：{主题}

### 涉及素材
- raw/file1.md — 来源A
- raw/file2.md — 来源B
- raw/file3.md — 来源C

### 来源对比
| 维度 | 来源A | 来源B | 来源C |
|------|-------|-------|-------|
| 观点 | ... | ... | ... |
| 侧重点 | ... | ... | ... |

→ 触发 Counter-Arguments
```

### 判断不准 entity_type 时

保守策略：先按 `concept`（默认），在 Analyze 中标注不确定性，询问用户确认。
