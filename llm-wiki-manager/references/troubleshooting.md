# 故障排查指南

> 本文件为故障排查参考。核心工作流、行为规范见 [`SKILL.md`](../SKILL.md)。

---

## 常见问题

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| search 命令报错 | 可能是索引未建立 | 先运行 `search.py --rebuild` 重建索引 |
| pages/ 下文件太多记不住 | 即达到 Scala 2 规模 | 建议划分子目录，建索引 |
| 中文搜索不准确 | grep 不支持中文分词 | 运行 `search.py --rebuild` 建索引 |
| URL 抓取失败 | 网络问题或反爬 | 手动复制内容后 `--stdin` 导入 |
| lint 输出大量孤悬页面 | 可能是未建立链接 | 分析后逐页面确认：补链还是缺口 |
| 用户问的内容 wiki 里没有 | 知识覆盖不足 | 主动建议导入相关资料 |
| 搜索返回空结果 | FTS5 索引损坏或不完整 | 运行 `search_engine.py rebuild` 重建索引 |
| concepts_index.json 解析失败 | JSON 损坏或空文件 | 运行 `detect_concepts.py` 重新扫描所有页面 |
| raw 素材乱码 | 编码非 UTF-8（如 GBK） | `Get-Content -Encoding UTF8` 显式指定编码读取 |
| 脚本返回 exit code 1 | 通用错误 | 检查输出文本中的错误描述，确认具体原因后重试或修复 |

## 异常恢复

### 元数据损坏

`meta/` 下的 JSON 文件损坏时，按优先级恢复：

| 损坏文件 | 影响 | 恢复命令 |
|----------|------|----------|
| `concepts_index.json` | 三层查询 L1 降级到 L2 | `python scripts/detect_concepts.py` |
| `source_map.json` | 无法追溯页面来源 | 下次 `compile_post.py` 自动重建 |
| `filename_index.json` | 重名检测失效 | 下次 `compile_post.py` 自动重建 |
| `feedback_log.yaml` | 权重更新无数据源 | 删除后自动重建空日志 |
| `page_weights.json` | 动态权重失效 | `python scripts/update_weights.py` |

> ⚠️ **检查点**：检测到元数据异常时，先告知用户影响范围（搜索精度降级 / 来源追溯中断），再执行恢复。

### 搜索索引异常

```
症状：search.py 返回空 / FTS5 报错
    ↓
先验证：python scripts/search_engine.py stats  # 检查索引状态
    ↓
异常 → python scripts/search_engine.py rebuild  # 重建
    ↓
回退方案：grep 全文搜索（精度低但可用）
```

### 并发编辑冲突

多个会话同时修改同一页面时的保护策略：

1. **编辑前检测**：读取目标段落，确认与预期一致（简单乐观锁，检查文件最后修改时间）
2. **冲突发现**：`edit` 工具返回匹配失败 → 页面已被另一会话修改
3. **处理方式**：
   - 重新读取最新版本，合并后再次尝试
   - 如合并困难（语义冲突），**输出 Structured Diff** 展示冲突内容，告知用户手动仲裁
   - **禁止自动覆盖**另一会话的修改

### 批量操作部分失败处理

批量操作（如导入多个 URL、批量 lint 修复）时：

- **默认行为**：逐条处理，单条失败不影响其余条目
- **失败记录**：输出失败条目清单（文件名 + 错误原因），末尾汇总
- **用户确认**：失败条目 > 30% 时，暂停并询问用户是否继续
- **幂等保证**：已成功处理的条目不重复执行（通过 `outputs/queries/` 去重）

### 网络异常处理

`web_fetch` 抓取 URL 时：

- **超时**：单次超时默认 30s，不自动重试；记录 URL 和错误类型
- **HTTP 4xx/5xx**：记录失败 URL 到 `outputs/reports/failed-urls.md`，提示用户手动导入
- **编码错误**：记录原始 content-type，提示用户确认是否为乱码
- **失败 URL 累积 > 10 条**：主动建议用户"是否要批量重试或转为手动导入"

### 大文件素材处理

| 素材大小 | 策略 |
|----------|------|
| < 50KB | 直接全量读取 |
| 50-200KB | 分 2-3 次读取，每块独立输出摘要，LLM 合并为完整内容 |
| > 200KB | 先读前 50KB 判断结构，再按章节定向读取 |

**分块合并规范**：
1. 每块独立提炼核心内容（1-3 句话），不逐字引用
2. 末尾输出"合并摘要"，列出各块贡献的核心知识点
3. 将合并结果作为 Single-Chunk 输出给 Analyze 步骤，避免中间状态污染

### compile_post 部分失败回滚

`compile_post.py` 4 步原子化执行。任一步失败时：
- 已完成的步骤不回滚（缓存/索引/概念各自独立）
- 输出失败步骤的错误信息和建议修复命令
- 用户修复后重新运行 `compile_post.py`，脚本自动跳过已完成的步骤

### 编码异常

raw 素材可能来自不同来源（微信/网页/本地文件），编码不统一：
- 优先用 `Get-Content -Encoding UTF8` 读取
- 乱码时回退 `Get-Content -Encoding Default`（系统默认编码，中文 Windows = GBK）
- 写入统一用 UTF-8 无 BOM
