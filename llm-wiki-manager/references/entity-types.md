# 实体类型系统

> 本文件由 `schema/entity-types.yaml` 自动派生。以 YAML 为准。

Wiki 文章按 12 种实体类型分类（6 基础 + 6 扩展）。每种类型有不同的必需章节和写作侧重。在 Two-Step Compile 的 Analyze 阶段确定类型，在 Generate 阶段按类型选择章节结构。

---

## 分类优先级（必须按此顺序判断）

1. 内容主要是**具体实现/架构方案** → `implementation-detail`（基础）
2. 内容主要是**步骤化操作指南** → `tutorial`（基础）
3. 内容主要是**外部资料/论文笔记** → `reference`（基础）
4. 内容主要是**场景实践/案例复盘** → `case-study`（基础）
5. 内容主要是**主观观点/思辨** → `opinion`（基础）
6. 内容主要是**抽象概念/理论/算法** → `concept`（基础，兜底默认）
7. 内容主要是**两个或以上方案的对比** → `comparison`（扩展）
8. 内容主要是**架构/技术决策记录** → `decision-record`（扩展）
9. 内容主要是**故障排查/问题诊断** → `troubleshooting`（扩展）
10. 内容主要是**语法速查/命令参考** → `cheat-sheet`（扩展）
11. 内容主要是**领域综述/趋势分析** → `survey`（扩展）
12. 内容主要是**编码规范/团队约定** → `standard`（扩展）

---

## 类型定义

### 基础类型（6 种）

#### `concept` — 概念/理论（默认类型）

适用于抽象概念、理论框架、算法原理。

**必需章节：**
- **定义与核心思想** — 2-4 句精确定义
- **关键原理** — 概念的核心机制
- **相关页面**
- **来源**

**示例**：Transformer Attention 机制、反向传播算法

#### `implementation-detail` — 实现细节

适用于具体技术的实现方式、架构设计、技术选型。

**必需章节：**
- **方案描述** — 具体实现方案
- **关键考量** — 权衡与决策点
- **相关页面**
- **来源**

**示例**：Redis 跳表实现、PostgreSQL MVCC 机制

#### `tutorial` — 教程

适用于步骤化操作指南、最佳实践文档。

**必需章节：**
- **前提条件** — 环境/知识要求
- **步骤** — 可执行的步骤列表
- **相关页面**
- **来源**

**示例**：FastAPI 从零搭建 REST API、Docker 部署 Django 应用

#### `reference` — 参考资料

适用于外部资料索引、论文总结、书籍笔记。

**必需章节：**
- **来源** — 原始资料链接/引用
- **核心内容** — 关键摘录和总结
- **相关页面**

**示例**：Attention Is All You Need 论文笔记

#### `case-study` — 案例分析

适用于具体场景下的实践分析、案例复盘。

**必需章节：**
- **背景** — 场景上下文
- **方案** — 采取的方案
- **结果** — 效果与复盘
- **相关页面**
- **来源**

**示例**：某电商平台订单超时方案复盘

#### `opinion` — 观点

适用于主观观点、思辨分析、对立观点讨论。

**必需章节：**
- **主张** — 核心观点陈述
- **论据** — 支撑论据
- **相关页面**
- **来源**

**示例**：为什么我认为 Rust 比 Go 更适合系统编程

---

### 扩展类型（extensions，6 种）

#### `comparison` — 对比评估

适用于多种方案/工具/方法的对比。通常由查询结果 promote 而来。

**必需章节：**
- **对比维度** — 评估维度定义
- **各方特点** — 每个方案的特点
- **结论** — 适用场景推荐
- **相关页面**
- **来源**

**示例**：PyTorch vs TensorFlow 选型对比

#### `decision-record` — 架构决策

适用于架构决策记录（ADR），含决策背景和论证过程。

**必需章节：**
- **背景** — 决策上下文
- **方案** — 候选方案
- **论证** — 加权对比
- **结论** — 最终决策与理由
- **相关页面**
- **来源**

**示例**：选择 Redis Streams 还是 Kafka 作为事件总线

#### `troubleshooting` — 问题诊断

适用于常见问题排查步骤和解决方案。

**必需章节：**
- **现象** — 问题表现
- **原因** — 根因分析
- **解决步骤** — 可执行的修复步骤
- **相关页面**
- **来源**

**示例**：MySQL CPU 100% 排查指南

#### `survey` — 综述

适用于领域综述、趋势分析、技术全景图。

**必需章节：**
- **背景** — 领域概况
- **各派观点** — 不同视角
- **趋势判断** — 发展方向
- **相关页面**
- **来源**

**示例**：2025 年前端框架趋势分析

#### `cheat-sheet` — 速查表

适用于语法速查、命令参考、API 列表。

**必需章节：**
- **条目列表** — 结构化条目
- **相关页面**
- **来源**

**示例**：Git 命令速查表、Python 正则语法速查

#### `standard` — 规范

适用于编码规范、设计规范、团队约定。

**必需章节：**
- **适用范围** — 何时适用
- **规则** — 具体规则条目
- **违反后果** — 违反的影响
- **相关页面**
- **来源**

**示例**：Python 代码风格规范、REST API 设计约定

## Frontmatter 用法

```yaml
---
entity_type: concept  # 从 schema/entity-types.yaml 的 12 种类型中选择
confidence: high      # high | medium | low
domains: [AI, 深度学习]  # 知识领域（可选）
tags: [关键词1, 关键词2] # 搜索标签（可选）
aliases: [别名1, 别名2]  # 跨语言同义词（可选）
created: YYYY-MM-DD      # 页面创建日期（可选）
updated: YYYY-MM-DD      # 最后更新日期（可选）
sources: [...]           # 来源数组（必需）
---
```

### extensions 的 tags 字段

`extensions` 类型在 `entity-types.yaml` 中预定义了一组分类标签（如 `[cross-reference, analysis]`），用于 lint 和索引阶段的二次分类。LLM 编译页面时，可在 frontmatter `tags` 中沿用或扩展这些标签。

### 子类型

如果标准 12 类不够细分，可以在 `tags` 中添加子类型标签（如 `algorithm`、`framework`、`methodology`），但 `entity_type` 字段只使用 schema 定义的类型。

## 判断不准时

保守策略：先按 `concept`（默认），在 Analyze 中标注不确定性，询问用户确认。
