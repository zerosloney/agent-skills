# 延迟队列

## 定义与核心思想

延迟队列是一种消息队列机制，允许消息在指定时间后才可被消费者处理。与普通队列的先来先服务不同，延迟队列根据预定时间触发消息，常用于订单超时、定时任务、延迟通知等场景。

## 关键原理

### 实现方式

**时间轮算法**
- 时间被划分为多个槽（slot），每个槽代表一个时间单位
- 消息根据延迟时间放入相应槽
- 时间轮定期转动，处理当前槽中的消息
- 时间复杂度 O(1) 插入，O(1) 取出

**Redis ZSet**
- 利用 ZSet 的有序特性，score 为目标时间戳
- 使用 ZRANGEBYSCORE 获取可处理的任务
- 使用 ZREMRANGEBYSCORE 清理已完成任务

**RocketMQ Delay Level**
- 支持 18 个预定义延迟级别（1s 2s 5s ... 2h）
- 延迟时间段固定，不够灵活但性能优异

### 权衡

| 方案 | 优点 | 缺点 |
|------|------|------|
| 时间轮 | O(1) 操作，性能高 | 时钟精度受限，内存占用不均匀 |
| Redis ZSet | 精度高，易于实现 | 移除过期数据需要额外索引 |
| RocketMQ | 落盘可靠，已集成 | 粒度固定，不支持自定义延迟 |

## 应用与实例

### 订单超时处理
```
用户下单 → 延迟队列（15分钟） → 未支付 → 自动取消
         ↓                ↓
      已支付 → 取消延迟任务
```

### 定时任务调度
- 替代 Crontab，支持动态任务的添加和删除
- 分布式环境下的任务分发和去重

### 延迟通知
- 活动开始前 30 分钟提醒
- 会员到期前 7 天续费提醒

## 常见问题

- Q: 延迟队列和普通队列有什么区别？
  A: 普通队列是先来先服务，延迟队列是根据预定时间触发。延迟队列内部通常使用时间轮或有序数据结构实现。
  来源：用户问答 2026-05-15

- Q: Redis ZSet 实现延迟队列的性能如何？
  A: 读写操作都是 O(log n)，适合中小规模场景。超大规模（百万级）需要考虑分片或使用 RocketMQ 等专用队列。
